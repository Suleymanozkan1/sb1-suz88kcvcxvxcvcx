# FLUX DROP — Review Findings Tracker (critical and major)

Every critical and major finding of the substitute reviews (CodeRabbit could not run, see
`docs/CODERABBIT_REPORT.md`) as one row: issue, fix, fix commit, regression test, verification and status.
Critical rows come first, then major; inside each severity the rows follow the milestones M1–M10 of the
CodeRabbit report. Minor findings (107) are summarised in `docs/CODERABBIT_REPORT.md` and are not repeated here.

## Method: issue → task → fix → test → full-suite re-run → verify

1. **Issue.** A reviewer that did not write the code reports a defect with a concrete reproduction (a headless
   probe or a failing test). Integrated-review (R-INT) findings also go to a second, skeptical verifier per area
   that tries to refute them on the current code.
2. **Task.** Each confirmed finding becomes a fix task, ordered critical before major before minor.
3. **Fix.** The fix is committed with the review round: module reviews on `review/<module>` (merged into the
   branch), integrated rounds as one commit per round (`d107839`, `055562e`), then `26c2427` / `4d3eb5f` for the
   requirement assessment (R-STATUS) and the final review (R-FINAL). Because fixes were committed per round,
   a round's critical, major and minor fixes share one commit; this tracker orders them by severity.
4. **Test.** A regression test that fails on the old code is added where the behaviour can be driven headless
   (module reviewers ran a mutation check: new tests fail on the original code).
5. **Full-suite re-run.** The whole suite runs after each round (`godot --headless --path game -s
   res://tests/run_tests.gd`): 746 tests at `4d3eb5f` (`docs/FINAL_IMPLEMENTATION_REPORT.md`), 778 at `83c86ef`
   (commit message); see "Re-run for this tracker" below.
6. **Verify.** R-INT round 1 was re-checked by the verifier after `d107839`, which re-ran the original probes and
   confirmed three residual defects (fixed in `055562e`); round 2 findings were confirmed before their fix.

Sources: `docs/CODERABBIT_REPORT.md` (totals and milestones), the fix commit messages, and the reviewers' raw output kept outside the repository (integrated-review finder and verifier records, the module-review issue lists, the independent security report); probe results quoted under Verification come from those records.

Column notes: test paths are relative to `game/tests/`; every `file::test` named here exists in the repository
(checked with grep when this file was written). "None dedicated" means no automated test drives that behaviour;
those rows were verified by re-running the reviewer's probe (probe scripts were not committed), and they are the
open part of the loop (see the summary at the end).

ID prefixes: `R-SAVE`, `R-ECON`, `R-FEEL`, `R-PROG`, `R-PLAT`, `R-COS`, `R-ONLINE`, `R-META` are the module
reviews (C = critical, M = major, numbered in the reviewer's order); `app-flow-*`, `gameplay-core-*`,
`ui-screens-*`, `view-perf-*`, `security-data-*` are R-INT finder ids; `SEC2-*` is the independent security/data
reviewer (its own report used `security-data-01…10`, renamed here to avoid a clash); `R-STATUS-*` are the defects
found by the requirement assessment.
